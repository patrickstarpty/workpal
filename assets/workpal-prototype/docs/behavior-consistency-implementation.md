# 第二轮行为一致性与 Squads 修复

本轮针对第二轮评审中的业务规则，以及 Squads Assign work / 成员 emoji 反馈实施修复。保留 Workpal 英文、中性紧凑视觉及无依赖离线单 HTML。未改变两份评审报告的历史发现。

## 操作与交付规则

- Issue 创建、属性编辑和看板状态操作统一使用 `updateIssue`。一次保存最多派发一次：进入 Review 生成 review；不启动选项覆盖普通分配和 Workflow；改派只停止原负责人的运行，保留其他 Agent 的并行工作。
- 保存前显示目标状态、实际负责人、是否排队和将停止的运行。人工改为 Done 必须填写理由，记录为 manual completion，与 delivery acceptance 分开；历史完成记录在重新打开后仍可查看。
- `currentDeliveryId` 指明当前正式交付。Delivery 版本只表示提交记录的顺序，不再用 Run 编号判断是否能评审。并行/迟到结果保留为 candidate，不覆盖现有交付或人工完成。
- 候选页提供 `Select for review`：填写理由后才切换当前交付，并明确将 Issue 移到 In review。原始来源和替代关系保持不变，选择记录独立保存。已评审版本不能改写其决定。
- 取消另一次尝试后，原来的当前交付仍可评审。顺序返工仍保留 v1 决定、v2 和比较入口。审批继续校验输入快照、产物、证据和确认。

## 输入与本地存储

- Delivery、Review、评论、笔记、任务和委派表单按 Workspace / 浏览器标签页 / 表单类型 / 对象保存草稿，布局重绘、导航和刷新后恢复。成功提交才清除草稿。
- 工作区保存使用 base / local / latest 三方比较，合并独立记录与笔记。相同记录有并发冲突则拒绝覆盖，保留本页内存和草稿。
- 冲突时可导出 JSON，或保留本地恢复副本后重载已保存工作区。恢复按钮放在当前原生弹窗内部，保持键盘及鼠标可访问。恢复副本保存在本地，不上传。
- 这仍是本地文件与 localStorage，不是多人同步或数据库事务。跨标签页冲突采用明确失败与恢复，不自动推断哪一份同记录修改更正确。

## Squads

参照本地 Multica 源码确认，Assign work 是预设 Squad 的新建 Issue，不是已有任务选择器。按钮移到标题区，窗口采用紧凑标题/描述编辑、属性行和折叠验收条件。

任务归属保留为 Squad；只有选中排队且处于 To do 时，创建一条 Leader 请求，运行快照包含 Squad 名称、Leader、成员、角色和指令。未实现多成员自动拆分、真实执行或汇总。

成员头像提供建议 emoji、粘贴一个完整组合 emoji、恢复默认。头像存于 Agent/成员身份，Squads、Agent 列表、Issue 和聊天共用；所有用户内容以文本转义呈现。

## 验证与边界

`npm run check` 验证模型、迁移与存储回归并构建离线文件。浏览器脚本覆盖已有主流程、Delivery、Squads、Lifecycle、Drafts、Chat/Inbox/Autopilot，以及五种尺寸布局。测试用隔离浏览器上下文；未修改评审者的现有浏览器数据。

内容仍由本地操作者填写，未调用模型、修改远程仓库或运行真实研发任务。证据门禁判断材料是否齐备，不把用户输入当作已测量的结果。工程、摘要与回复已有可完成的路径；任意任务类型的策略系统和生产调度不在本轮范围。
