# Separate functional and technical design

Corrected SMART-2, SMART-7, SMART-8, SMART-14, SMART-15 and SMART-20. Their original functional Word documents are now named FDS (Functional Design Specification), with corrected identifiers, headers and footers. Each ticket also has a separate TDS (Technical Design Specification) describing proposed implementation details and explicitly referencing its FDS.

For SMART-15, the FDS describes reading/editing, Save/Cancel, error recovery, keyboard access and acceptance. The TDS describes editor state, the authenticated PATCH boundary, persistence, a proposed concurrency contract and verification boundaries. A proposed concurrency contract is not represented as implemented.

The existing document-import activity was corrected to identify the FDS. A subsequent TDS activity was added with its own attachment. Historical authored notes were corrected for terminology but remain filtered as execution history. Ticket/project status was preserved. Original document bytes were retained in design_original_contents, and a pre-change SQLite backup was created.

All 12 documents are stored completely in SQLite and served through authenticated attachment endpoints. Verification checked XML well-formedness, document identifiers, SHA-256, six FDS-before-TDS activity pairs and unchanged status values. The SQLite-only HTTP verifier reads 131 business records and downloads all 78 current documents. Word page rendering was not performed because LibreOffice is unavailable.

scripts/correct-design-specifications.py applies this correction once. Existing functional-document generator and publisher scripts are now named create-smart-fds.py and publish-smart-fds.py.

Final validation: npm run check passed, and the SQLite-only HTTP verifier passed for 131 records and 78 complete documents.
