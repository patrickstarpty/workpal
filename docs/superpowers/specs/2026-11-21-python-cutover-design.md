# Python 前后端对接与 Node mock 退役设计

状态：设计稿。用户已确认保留 `npm start`，以简单统一入口启动完整应用；本轮不修改运行代码或数据库。

## 目标与约束

以现有 React 前端、Python FastAPI 和 SQLite 为唯一业务运行链路。严格遵守：先对接、再验证、最后删除 Node mock 服务、自动填充逻辑及专属测试，并调整关联脚本。保留 Workpal 品牌、英文 UI、键盘与窄屏访问；不执行技能安装命令，不调用真实模型。生产集成与生产身份提供商不在本次范围。

“正式对接”表示真实 HTTP/WS 请求、权限校验和 SQLite 持久化，不表示已具备生产部署能力。现有开发登录仍需显式启用且只能绑定回环地址；不将固定开发验证码视为生产认证。

## 现状与证据

- `package.json` 的 dev/start/check/test 仍面向根目录 Node mock。
- `scripts/python-web-dev.mjs` 已串联迁移、worker、API readiness 和 Vite；仍需显式数据库配置。
- `apps/web/vite.config.mjs` 仅在 python mode 代理完整 API/auth/WS 路径。
- Python 已有身份、工作区、成员、邀请、内容、实时事件及历史数据导入实现。覆盖程度须验证，不因代码存在就视为完成。
- 只读检查发现旧 SQLite 有 1,225 条 records，Python SQLite 有一条 legacy_imports；这不证明全量一致，也不允许覆盖之后的编辑。
- Python 暂无构建产物静态托管；不能直接把 npm start 指向 API serve 后宣称替换完成。
- `scripts/python-workspace-import-qa.mjs` 仍通过 Node store 构造测试来源，退役前必须解耦。

## 方案选择

采用在现有 Python 实现上补齐连接与验收的渐进切换。Node 在验证阶段仅使用隔离副本作旧行为对照，不作为新链路失败时的隐式回退。

不直接删除后重建：无法满足先验证后删除。不一次性重写所有内容表：现有 workspace_records 已提供受工作区约束的持久化，全面领域重构会扩大迁移风险，本次保留该结构与原始 source_body。

## 目标结构与运行方式

`server/` 保留 `src/workpal_backend/`、`tests/`、`migrations/`、`contracts/`、`tools/`、Python 配置及锁文件。`data/` 原位保留；`go/` 保持参考用途。检查残留 `server/python/tests` 的内容与引用后再决定合并，不凭目录名删除。

开发：npm dev/dev:web 启动 Python API、worker 和 Vite，同源代理 `/api`、`/auth`、`/ws`、`/v1`、`/plugin-surfaces`。保留现有 docs 开发体验或提供明确独立命令。

构建运行：保留现有 `npm start` 命令作为统一入口，不要求用户分别启动前后端或配置 Nginx。`npm run build` 生成前端产物；`npm start` 通过轻量进程启动器运行 Python API/worker，由 Python 安全托管该产物。Node 只承担 npm 命令与进程启动，不再提供 mock API。API、认证、WS 与未知后端路径不能回落为 index.html；静态路径必须阻止目录穿越；缺失产物必须给出可操作错误。开发与构建运行分别验收。

启动器统一处理配置、端口冲突、readiness、失败退出及进程组清理。提供配置示例但不提交密钥；不自动关闭外部进程、不清空 Redis、不自动填充业务数据。Redis 继续承担事件与任务基础设施，SQLite 是业务数据源。

## 数据迁移与对账

1. 读取现有导入清单、源摘要、按 kind 的计数和 ID 映射；核对源原文、归属和关联，不仅比较总数。
2. 当前删除会连同 source_body 一起删除；manifest 只有汇总计数和映射，没有逐条删除凭据。already_imported 与计数一致都不能证明当前完整性。对账现存 source_body 与源快照；任何无法证明原因的缺行都必须阻断验收，不能推断为合法删除，也不能自动补回。后续编辑不得覆盖。
   本次采用保守阻断方案，不新增历史删除自动识别。若未来需要自动识别，必须另行设计独立于业务行、不可随业务删除丢失的逐条快照，以及与删除事务一致提交、含记录标识/时间/操作者/来源的删除凭据；事后新增机制不能追认历史缺行。
3. 若导入一致，跳过写入；仅在不存在导入清单且无目标冲突时使用显式 import-legacy。已有清单下的缺行不是“缺失导入”。源已变化或目标冲突时停止，不以覆盖或清库“修复”。
4. 真正写入前协调写入进程，通过 SQLite backup API 备份源与目标，记录恢复步骤；不得只复制主文件遗漏 WAL。保留原库、备份与本地审阅资料。
5. 空库通过 schema migrations 和正常用户操作初始化，不自动导入 seed.json 或生成业务记录。测试使用隔离 SQLite 和最小合成夹具。

## 最终切换与停止写入

早期审计只是预检，不能作为最终删除许可。最终切换前进入维护窗口：停止旧 Node 服务和所有旧库写入者，禁止自动重启；暂停 Python API、worker 及其他目标库写入者。记录停止时点与进程/入口检查证据，通过 backup API 制作一致性备份。仅停止一个 HTTP 服务不足以证明已停止写入。

在冻结状态下重新计算源逻辑摘要（与导入器相同算法），与预检基线及 manifest 比较，并重新完成目标逐条对账。任一摘要变化或无法解释的差异使早期证据失效，必须停止切换和删除，另行处理差异后重新验收；不得直接重跑导入掩盖冲突。旧行为对照和写入测试仅使用隔离副本。

最终报告绑定源摘要、目标一致性快照、迁移版本、应用版本和时间。通过后只恢复 Python 写入；旧库持续封存且旧启动入口不得重新启用。若冻结后又出现旧库写入，立即撤销放行，重新冻结与对账。

## 前后端对接边界

以当前应用实际发起的请求和 `server/contracts/` 为基础，登记方法、路径、认证/CSRF、workspace、响应结构及错误。按登录→能力入口→工作区→项目/任务/评论→设置/成员→历史内容逐条核对。已有可用 CRUD 必须保留；未实现能力返回明确错误，前端可展示并恢复交互，不用空成功掩盖。

实时验证包含订阅权限、事件送达、重连和登出失效；不将 Redis 发布成功等同于浏览器收到更新。历史统计只读既有持久化记录，不生成新的执行结果或测量值。

## 删除门槛：所有条件均满足

- **数据**：导入快照逐类/关联/原文对账；重跑幂等、冲突拒绝、失败回滚测试通过；现有编辑不被覆盖；无法证明原因的缺行一律阻断，最终冻结后的源摘要与目标对账通过。
- **接口**：Python 测试通过；登录、CSRF、跨工作区拒绝、写入权限及不支持操作的错误均有验证。
- **浏览器**：Playwright 通过登录、进入原工作区、项目/任务详情与评论、代表性创建编辑删除、刷新及服务重启后的持久化、退出登录；覆盖键盘与窄屏。写入测试使用隔离库，真实库仅做必要只读核对。
- **实时与运行**：WS 正常更新/重连、会话失效；Redis 不可用、端口冲突、子进程退出、SIGINT/SIGTERM 不留孤儿；开发和构建运行分别通过。
- **回退**：记录已通过验收、npm start 仍指向当前 Python 数据库的具体提交 SHA、构建产物与配置；验证兼容当前 schema，且切换后新增记录在回退后仍可读。不得以旧 Node 版本作为回退点。
- **项目检查**：切换后的 `npm run check` 包含 Python 测试、所需脚本检查及前端构建，全部通过；保存命令、退出码、测试摘要和未覆盖项。任何关键跳过不能算通过。

未通过时保留 Node 文件，记录失败项并继续修复，禁止进入删除阶段。

## 删除阶段与最终复验

通过门槛后删除根目录 Node API/store/start、自动填充模块、seed.json 和确属旧服务的测试；先确认 fixture 的消费者。历史导入工具、隔离测试夹具不是运行时 mock，应保留。

将仍有产品回归价值的旧 QA 改为对 Python 运行，真正专属旧实现的脚本才删除。解耦 Python 导入 QA 对 Node store 的依赖。更新 npm 命令、README、server README 及适用仓库说明；历史记录不全局替换。删除后的活跃代码/脚本不得引用旧模块。

再次运行完整 check 与上述浏览器验收，记录删除前后证据。保留数据库及备份，不将历史数据清理混入源码退役。回退只能使用删除前保留的、已验证的 Python 兼容版本（实施时必须填入具体提交 SHA，不能只写“上一个版本”），继续指向同一 Python 数据库并保持旧库停写。记录当前 schema revision、配置和构建产物；后续迁移若破坏兼容性须重新验证回退点。隔离环境演练：切换后新增记录→停止写入→回退应用→验证同库记录可读且后续写入仍进入该库。没有兼容版本时保持维护状态，不启动旧 Node、不自动降级 schema，也不以旧备份覆盖新写入。
