# Multica Go 后端逐项等价复刻设计（待用户审核）

状态：**仅设计，未获实施批准。** 用户于 2026-11-22 要求停止实施、核对 Go 源码、重写文档，审核后才可开始。本文件替代旧设计中允许先按本地页面完成切换的执行解释；不表示当前 Python 已完成迁移。

## 1. 目标与“一比一”的定义

以本仓库保留的 Multica Go 后端为唯一行为基准，把其后端行为复刻为 Python。不是把 Node mock 换一种语言，也不是重新设计一个功能近似的简化后端。

等价单位是一个完整行为：入口及中间件 → 身份与权限 → 参数解释 → service 分支 → SQL/事务 → 返回值、错误和事件 → 后续可观测结果。路径存在、HTTP 200、页面可打开、测试数量多，都不单独构成等价证据。

必须保持：方法/路径、请求头和表单字段、字段缺省与 null、状态码及错误体、排序分页、资源可见性、角色和 token 类型边界、状态迁移、软删/级联/恢复、持久化、幂等、事件与失败恢复。不得使用通用 JSON CRUD 绕过 Go 的业务限制。

## 2. 固定源码基线与审计边界

本次文档核对的 Git HEAD 为 `c4a7c6f87f5abade4297fc18796f3f726c1db7f6`。Go 源码、嵌入资源、依赖锁与配置初始化文件的内容摘要、逐路由索引和已确认差异见 [源码核对记录](../evidence/2026-11-22-go-parity-source-audit.md) 与同目录 `2026-11-22-go-source-sha256.json`。开始实现前重新校验摘要及受保护文件集合（新增/删除也必须失败）；任何受保护输入变化均使相应证据失效，不能混用版本。

固定基准构建 profile 为 Go 1.26.9、GOOS=linux、GOARCH=amd64、CGO_ENABLED=0、GOWORK=off、GOFLAGS 空、显式 tags=[]（默认 !oss，包含 ee 注册）。这是待批准的差分构建目标，尚未实际构建。禁止继承宿主隐藏 tags；`oss` 构建必须另建独立 profile 和路由账本，不能用于减少默认版本的接口范围。Go 依赖按 go.mod/go.sum 锁定；缺少该工具链应记录阻塞，不静默升级。

源码顺序：

1. `server/go/cmd/server/{main,router}.go` 和其注册/初始化依赖：HTTP、WS、内部入口、全局及嵌套路由中间件、配置和生命周期。

5. `server/go/internal/scheduler/`、事件消费者及 main 注册的后台任务：非 HTTP 行为；不能因为前端不调用就遗漏。
6. Go 调用的存储/插件/渠道等依赖：接口与回调也必须追踪；客户端调用仅做交叉检查，不能决定迁移范围。

复刻对象为 Go **后端服务及其对外协议**。现有 Go CLI、daemon 可执行程序保留，后端面向这些客户端的 API/WS 协议仍在范围内；“不改写 CLI 二进制”不等于删除 daemon API。

## 4. 存储与配置决策

保留现有 Python/FastAPI、SQLite 和 Redis 技术方向作为待审核方案，不在本轮擅自换数据库或改运行配置。SQLite 与 Go/PostgreSQL 并不天然等价：每个 FK、唯一键、部分索引、JSON/数组查询、全文搜索、排序规则、时间精度、锁和 job claim 都要有转换说明和等价测试。

无法证明等价的 PostgreSQL 行为必须阻塞对应任务并提交具体方案（包括是否改用 PostgreSQL）给用户审核，禁止用一个通用 JSON 表或单进程假设悄悄缩小语义。Go 并发、锁及重试保证不能仅以“SQLite 只有一个写入者”代替。现有 SQLite 原数据一直保留，任何后续存储决策都另列迁移和回退方案。

配置沿用上游 `.env` 初始化和复用方式：首次生成随机密钥，已有配置不覆盖；启动时加载，按原配置优先级处理。优先兼容 Go 的 `JWT_SECRET`、`APP_ENV` 等名字及验证规则；当前 `AUTH_SECRET`、`WORKPAL_ENV` 等 Python 名字列为待审计兼容别名，不能再发展另一套配置标准。旧密钥不得回显。生产拒绝不安全默认值、开发行为及警告逐项对照 Go。Node 仅可作前端工具/启动器。

## 5. 模块与实施方法

保留现有基础设施，但一切已有实现重新按 Go 核验。每个领域拥有 routes/schema/service/repository；只有确实等价的基础能力才共享。`workspace_content` 现有适配层视为待替换/重构对象，不作为 Go 标准。

按依赖迁移：配置和基础设施 → 身份与工作区 → 资源权限和核心业务 → 附件、聊天、搜索、通知等完整行为 → 插件/集成协议 → 调度和事件全覆盖 → 全量验收 → 最后切换与退役。后台事件随其业务事务同时实现，不能留到最后仅验证一条 WS 消息。

附件必须对照 Go 全链：100 MiB 上传边界、类型检测与扩展名、个人/工作区归属、issue/comment/chat/task 关联、task token 约束、私有资源授权、响应、下载/内容预览/删除和恢复。当前仅支持 5 MiB 图片的兼容接口不能算附件复刻完成。

**失败语义也必须复刻，可靠性增强不是默认等价。** `file.go:616–651`：字节上传成功、附件元数据写入发生普通非取消错误时，Go 记录日志并返回 HTTP 200，JSON 恰为 `{"id":"","url":link,"filename":原文件名}`；不进入成功附件的事件分支，不在此错误分支删除已上传字节。不能把这个对象自动标成需要回收的“失败上传”。内部 staging/ready/ledger 可以采用，但必须保持此分支可观测行为。

后续访问需按存储 profile 验证：S3/CDN 返回对象链接，是否可访问由原桶/CDN权限及配置决定；字节仍保留，不凭响应推断匿名公开。LocalStorage 返回 `/uploads/...` 或带 base URL 的链接，但当前 Go router 不公开本地 `/uploads`，`cmd/server/local_uploads_test.go:19` 要求 GET/HEAD 返回 404；缺元数据时不能凭空生成有效 attachment-id 下载入口。分别记录字节存在、返回链接、实际 GET/HEAD 结果及重启后结果，不能统一写成“返回链接必然可用”。

分开验证另外两个分支：评论锁返回 pgx.ErrNoRows 时调用 deleteS3Objects 并返回 403 `invalid comment_id`（删除调用不等于保证存储删除成功）；请求取消分支调用 writeRequestCancellation 后返回，保留字节以避免删掉可能已提交的附件。不得把它们与普通 DB 失败混为一谈。

拟改成非 200、隐藏链接、保证原子失败、自动回收或开放本地链接访问，均列为**待用户批准差异，默认不实施**。差分测试应对上述各分支注入故障，比较响应、事件、字节和后续访问，不能只比较成功上传。

项目/任务必须对照隐藏资源和私有权限、先过滤再分页、归档默认行为、工作流与状态、关系约束及事件。当前只验证工作区成员的通用 CRUD 不能算等价。
