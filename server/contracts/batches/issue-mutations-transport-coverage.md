Create issue and comment-subissue share success bucket insertion and recent visit recording, conditional parent children/progress invalidation, and settled list/flat/table/group/Gantt/sidebar/project invalidation. They have no optimistic rollback.

Single update selects PUT or relative-anchor move, omitting optimistic position from the latter request. Optimism excludes description merge/control fields, cancels loaded owner requests, uses the coordinator, and patches or removes old-parent children. Error restores coordinator/children snapshots and invalidates owners. Success omits the properties bag and admits only newer revision snapshots before revision reconciliation; done-agent status changes report to the local star prompt. Settle handles stale keys, derivatives, table, optional attachments, both duplicate sides and old/new parent queries. Inbox re-reads are owed only for interrupted/in-flight requests or failures; a mutation-cache terminal event pays the debt after the last workspace issue write finishes.

Batch update deduplicates first snapshots by key hash and patches loaded children. Labels/properties are sent but not predicted. Count-only partial success rolls back and invalidates owners; labels/properties force owner refresh at settlement. Derivatives, table, stale keys and affected parents refresh conditionally. Batch children are mapped rather than pruned on reparenting, unlike single-update children.

Single and batch delete cancel list/my/flat and discovered parent requests, capture snapshots and prune loaded lists/children. Single removes detail optimistically and restores it on failure. Confirmed success forgets recent context, cleans scoped caches and prunes inbox. Batch success requires deleted == requested length; otherwise it restores snapshots, invalidates issue/dependent caches and re-reads inbox and summary because the response does not identify survivors. Both settle aggregate/list/project and discovered-parent refreshes.

Comment create builds a sorted, ID-deduplicated timeline entry and preserves steering receipts; steered comments invalidate tasks. All successful creates invalidate trigger previews and revision-aware owners/activity-sorted lists, without a settled timeline refresh. Update snapshots and optimistically edits content and retained attachments, restores on error, refreshes owners/activity on success and timeline on settlement. Delete reads keep-replies capability at execution, applies confirmed tombstone/pruning or legacy subtree removal, refreshes owners/activity, and settles timeline. Local deletion helpers walk cached descendants and tombstone ancestors; incomplete cached replies require reconciliation.

Resolve/unresolve snapshots timeline and restores on error. Resolve clears other resolutions in the cached thread; unresolve clears only the target. Thread walks guard cycles. Settlement refreshes timeline. Comment reactions branch on supplied existing reaction and settle timeline; issue reactions similarly branch, record auxiliary revision on success and settle reactions. Neither reaction hook patches optimistically.

Subscriber toggle cancels/snapshots subscriber data, removes or adds a manual row; existing subscriptions lose delivery information until refresh. Error restores only a defined prior snapshot; an initially absent snapshot can leave an optimistic row until settlement. Subtree unsubscribe has no optimistic patch. Both settle subscriber queries and, for member writes with a current workspace, refresh subscribed IDs and issue queries whose serialized keys contain the subscribed relation. This helper cancels the ID request before invalidating it.

Cancel and retry run invalidate tasks only on success. Retry supplement settles timeline and tasks. No actual model execution is established by these frontend requests.

Rollback is local snapshot replay, not a server transaction or concurrency lock. Fire-and-forget invalidations/cancellations have no guaranteed ordering or request count. Enabled active matching observers may refetch; inactive entries can fetch later. The inherited refetch inventory is deliberately conservative. Arbitrary observer descendants and third-party internals are excluded.
