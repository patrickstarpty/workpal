## Decode and validation

UpdateMeRequest (auth.go:519) has five *string fields. One encoding/json Decode only: empty/malformed first JSON value, array/scalar root or wrong known-field type returns 400 `invalid request body`. Root null is accepted as all omitted. Unknown keys ignored; matching is case-insensitive as Go struct JSON tags permit. Trailing content after a complete first JSON value is not checked. Duplicate string keys overwrite; a later null resets the pointer, hence `{"name":"Ada","name":null}` preserves name. Earlier type errors still fail even if later duplicate is valid. Do not use a coercing Pydantic string model or a JSON parser that silently loses earlier duplicate type errors. Invalid UTF-8 / unpaired surrogate replacement follows encoding/json; fixtures must exercise replacement rather than Python decoder exceptions.

Missing and explicit null both preserve each field. No request default language/name/timezone is injected. GetUser occurs after decode but before validation: ANY lookup error, including SQL outage, returns 404 `user not found` (unlike GET /api/me). Validation order is name, avatar, language, description, timezone; first failure wins.

Name: Go strings.TrimSpace, nonempty or 400 `name is required`; no maximum length. Avatar: trim then policy below; empty string persists empty, not NULL. Language: trim; exact allowlist en, zh-Hans, zh-Hant, ko, ja, fr, es, ru; otherwise 400 `unsupported language`. Description: trim, <=2000 Unicode runes, otherwise 400 `profile_description exceeds 2000 characters`; empty persists empty. Timezone: trim; empty clears SQL NULL; nonempty accepted only by time.LoadLocation, otherwise 400 `invalid timezone`. This includes UTC, Local and names supported by Go zoneinfo, not only slash-containing IANA identifiers. Python ZoneInfo alone does not reproduce Local; define local-zone adapter and test deployed tzdata. Go whitespace differs from Python str.strip (notably U+001C–001F); use explicit Go unicode whitespace set.

## Storage and response

user.sql UpdateUser is one UPDATE RETURNING, always writes current/resolved name and updated_at=now(), even `{}` / root null / all-null / unknown-only payloads. Nullable avatar/language/description params use COALESCE; timezone uses NULL parameter=preserve, empty=clear, otherwise replace. Update error (including disappearance after SELECT) is 500 `failed to update user`. No explicit transaction spans SELECT and UPDATE in Go, no locking/version precondition, no publication or outbox. Existing name can overwrite a concurrent name update even when name omitted. Validation rejection does not update profile. Preserve that distinction from middleware auth side effects.

## Avatar policy and integrations

avatar.go:150–307 is required, not generic URL validation. normalizeStoredAvatarURL verifies served /api/avatars/<sig>/<key> paths (absolute URL path also accepted), then stores durable Storage.ObjectURL(key). Signature: base64url unpadded HMAC-SHA256(key), signing key SHA256('avatar-url:' + JWT secret). Invalid served signatures pass through as unowned URL. Storage=nil passes trimmed raw value through. Normalized unchanged value bypasses publishability validation. Third-party URLs, emoji markers, data URIs and unowned values pass through without fetching or validating scheme.

Owned means KeyFromURL then exact ObjectURL roundtrip. New owned object must have png/jpg/jpeg/gif/webp/avif/bmp/ico extension (case insensitive). Outside workspaces/ namespace this suffices. Inside it basename stem must be attachment UUID, GetAttachmentByIDOnly must succeed, content type lowercased must start image/, and issue_id/comment_id/chat_session_id/chat_message_id/task_id must all be NULL. Any failure including SQL error maps to the exact 403 in JSON. No upload ownership check. Do not claim to support this branch without attachment metadata.

Response resolution preserves null/empty and storage=nil. Valid served URLs reemit stable signature path, anchored to configured PublicURL. Owned allowed image objects use raw URL if publicly readable, otherwise signed avatar endpoint; local storage always uses endpoint. Unsupported extension/unowned values pass through. S3/CDN presigning, proxy downloads and attachment serving are other-route integrations, not actions this PATCH performs. Bounded implementation must inject explicit AvatarPolicy; use documented storage-disabled passthrough only when storage is actually disabled. Configured local storage requires real ownership/attachment checks, or explicit unsupported failure before mutation; never fake approval or generate pretend signed URLs.
