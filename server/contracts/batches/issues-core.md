## Identity and visibility

Router registrations: `server/go/cmd/server/router.go:2165-2191`; inherited authentication/workspace policy remains required (see auth-workspaces-health contract). Never accept workspace or creator from body as authority. `handler.go:1083-1135` resolves identifiers before UUID, scopes lookup to workspace, returns 404 for malformed IDs and inaccessible private-project issues. `project_access.go:18-90` uses member identity or trusted run originator plus agent owner; absent trusted principals do not grant private access. Access lookup failures return 500 `failed to resolve project access`. List excludes hidden projects before count/window; duplicate references and source snapshots must not leak them. Create rejects hidden project/parent with the same 400 messages as missing ones. Assignee access is separately checked against effective project, including inherited parent project.

Create actor uses `resolveActor`, with auth stripping forged X-Agent-ID/X-Task-ID and restamping validated task-token identity. Agent origin `agent_create` requires trusted task owned by acting agent; explicit origin accepts only paired quick_create + UUID. Preserve agent/squad authority checks (`validateAssigneePair`), including private-agent invocation and run-originator binding; do not reduce this to existence checks.

## Wire and frontend

Nullable pointers emit null unless tagged omitempty; status_name always emitted even empty, status_category can be absent when unresolved. duplicate_of is a resolved visible reference, not the stored ID. metadata/properties always objects. labels always authoritative arrays on these routes; create event also carries labels. ## SQLite translation and write boundaries

Use new database only. issue: text UUID PK; workspace_id required FK workspace cascade; title required; nullable description; status required catalog key (remove historical seven-status CHECK); priority CHECK urgent/high/medium/low/none; assignee_type nullable member/agent/squad with nullable assignee_id soft polymorphic ID; creator_type/id required polymorphic actor. Parent self FK SET NULL; project FK SET NULL; number required and unique per workspace. Persist position REAL, revision INTEGER, nullable stage INTEGER, start/due calendar TEXT, nullable last_activity timestamp, created/updated UTC timestamps, JSON metadata/properties and source/origin/requester/duplicate relationships. Validate tenant boundaries in service, not merely globally unique IDs. Relevant schema evolution is in migrations 020,034,091,105,112,123,191,332,337,360,407,483,536,643 and issue.sql; inspect later migrations before implementing DDL, since baseline enum/FKs are not final schema.

Labels: issue_label text UUID PK, workspace FK cascade, resource_type issue/agent/skill CHECK default issue, name/color required, description required default empty; uniqueness workspace/resource_type/LOWER(name) (`162`, `167` migrations). issue_to_label composite PK(issue_id,label_id); final SQL explicitly states junctions have no FKs: perform scoped existence validation and cleanup in application transaction, do not restore baseline cascading FKs. Actor catalogs member, agent(owner_id), squad and squad membership support assignment and indirect-user filtering; assignee_id is not a member-only FK.

Translate ANY arrays to bound IN/EXISTS, empty arrays to false, JSONB containment to structural containment (not string equality), typed property comparisons to definition-aware values, status rank to CASE, NULLS LAST explicitly, calendar comparisons and UTC timestamps consistently. PostgreSQL LOWER/ILIKE semantics require differential Unicode fixtures, not an assumption SQLite NOCASE is equivalent.

`service/issue.go:233-640` owns transaction. Validate properties, parent/project/workflow and archive state; inherit parent project where omitted; serialize duplicate guard and counter allocation; increment workspace counter; position below column minimum; insert issue, properties and scoped labels atomically. HTTP defaults todo/none differ from historical DB backlog. Workflow validates initial status and can choose handler when both assignee fields omitted. Counter/row/label/property failure rolls back together. SQLite short write transaction replaces workspace row/catalog advisory locks, revalidating status under transaction; unique workspace-number constraint remains collision backstop. Retry policy must follow collision classification, not retry every error.

Attachments link after commit, idempotently. `service/issue.go:589-640,787-807`: issue:created publishes after commit and attachment linking, then analytics and ordinary assignment enqueue. Envelope has workspace, actor_type/id and payload {issue: full projection}. Deferred channel tasks are a separate service option with atomic task insertion; ordinary HTTP creation must not accidentally adopt that ordering. Consumers include activity_listeners.go, subscriber_listeners.go, notification_listeners.go, plugin_event_bridge.go and realtime bus broadcast. Capture issue creation activity, creator/assignee subscriptions and assignment/delegation notifications with idempotent consumers. Python durable outbox belongs in issue transaction; delivery after commit must retain stable event ID, retry and duplicate handling. Redis failure after commit leaves durable pending delivery, not a false rollback response. No actual model execution: assignment-triggering paths require an explicit supported/unsupported policy before accepting writes that imply execution.
