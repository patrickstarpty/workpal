## Update and delete

Update (:3351) scopes comment to workspace, rejects tombstone 404, then private issue visibility, supplement binding, membership and author/admin checks. Only matching actor type AND actor ID is author; owner/admin can manage comments but gain no private-agent invoke authority. Supplement-bound comments cannot edit (409). Required content is sanitized before validation; positive expected_revision checked initially and again in SQL. content_base permits same desired content even when base differs. Stale strict write is 409 structured revision conflict (JSON fixtures). Missing/null attachment_ids preserves links; [] replaces with empty set. Content change clears inherited source task for human/admin edits; owning agent re-stamps current task. Unchanged content does not re-trigger. Strict changed-content edit cancels old tasks and settles terminal state inside same transaction as conditional update; attachment replacement shares transaction. Legacy non-strict edit cancels before update and replays survivors on failure. comment.sql:564–640 increments comment revision only for content/lineage changes; attachment-only changes explicitly bump once; identical edits do not bump. Issue revision/activity follows SQL mutation outcome; zero issue_revision omitted. Updated response includes current reactions/attachments; private trigger feedback added only after broadcast.

Delete (:3634, deleteComment :3834 onward) applies workspace/private visibility and author/admin gate. Already absent/tombstoned => 404. Cancel planned tasks before deleting so FK nullification cannot orphan queue work; cancellation failure is logged and deletion proceeds. Failed deletion replays cancelled survivors if issue remains. Transaction locks issue/comment then supplement receipts; pending/delivering receipt => 409 and rollback. Deletes receipts, attachments and reactions. With replies, clear content/resolution and set deleted_at, increment revision; retain ID/parent and every reply. Without replies, delete leaf and prune only now-replyless tombstone ancestors, nearest first, at most 256. Touch issue revision/activity in transaction. After commit clean storage objects, emit tombstone update and one delete per physically removed ID, replay surviving batch inputs. HTTP 204 empty body, including keep-replies alias. Original parent cascade must never delete live replies.

## Dependencies, events and SQLite translation

Read actual helper implementations: handler.go:624–664 error envelopes/CAS conflicts, :792 publish, :1083 issue loading; project_access.go:19–145 hidden project principals and fail-closed access; file.go:340 grouping (workspace scoped, load failure logs and yields empty response attachments); comment.go:3789 lockCommentAttachments and :3834 deletion; util/mention.go: ParseMentions parses canonical Markdown links, deduplicates, ignores code/images, includes blockquotes. Mention dependencies include member subscriptions/notifications, agent/squad invoke authority, task cancellation/coalescing/steering, source-task originator and suppression persistence. Never equate admin edit permission with invocation permission.

Go producers CreateComment/UpdateComment/DeleteComment call Handler.publish after DB commit. Envelope has Type, WorkspaceID, ActorType, ActorID, Payload (handler.go:792). Create comment:created payload contains comment, issue_title, nullable issue_assignee_type/id, issue_status, issue_revision. Update comment:updated contains comment and positive issue_revision; trigger_outcomes excluded. Delete comment:deleted contains comment_id, issue_id, positive issue_revision; tombstone uses comment:updated. Read emits none. Consumers include server/go/cmd/server/subscriber_listeners.go:108 (subscribe commenter), notification_listeners.go:1160 and realtime delivery/private project filtering (private_project_realtime_test.go). Scope is workspace with current resource authorization, not public broadcasting.

Python requirement differs from Go's in-memory postcommit publication: append stable-ID durable outbox event in the SAME SQLite transaction as each visible mutation, issue revision and attachment changes; no independent outbox commit. Auto-unresolve is its own mutation/event transaction. Worker retries Redis outages and deduplicates consumers by event ID; do not publish rolled-back changes. Trigger outcomes remain private response feedback. Unsupported execution must return explicit capability failure, not queued/fabricated runs.

Translate UUID to validated canonical TEXT; UUID arrays (suppressed agents) to normalized relation or JSON with validation; timestamptz to UTC text with stable ordering; bigint revisions to INTEGER, nullable UUID/time/type columns to NULL, bool to constrained INTEGER. Preserve workspace+issue tenant integrity, parent/task/attachment/reaction FKs and deletion policies, type/author checks, revision default 1, deleted_at migration 471, revision migration 351 and suppression migration 550. Replace PostgreSQL data-modifying CTEs and FOR UPDATE with bounded SQLite write transactions, conditional updates and row-count checks; retain issue/comment/attachment mutation atomicity. Recursive CTEs need cycle/depth bounds; replace ANY/UUID arrays explicitly. Durable file cleanup intent commits with deletion; bytes removed idempotently after commit and retried after restart. Never operate on existing Go/mock databases or object paths.
