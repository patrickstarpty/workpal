# PR view refresh event source contract

Bounded one-event evidence supplement to `issue-resource-read-events`. The JSON supplies the required-event fields and background producer identity for eventual inventory integration; it does not declare producer coverage complete, change route status, or claim runtime verification.

GET `/api/issues/{id}/pull-requests` loads an authorized issue and workspace, then linked GitHub rows (`server/go/internal/handler/github.go:1125`). Each GitHub card calls MaybeEnqueueOnView before subsequent VCS list/auto-complete decision reads, so a later HTTP failure does not undo an enqueue (`server/go/internal/handler/github.go:1150`). VCS rows do not use this refresh path. The GET returns its current possibly stale projection; computing the auto-complete decision does not apply an issue status change.

Gates: the manager/client must be enabled (`server/go/internal/integrations/ghsnapshot/refresh.go:141`, `server/go/internal/integrations/ghsnapshot/client.go:110`); Start is disabled-safe and idempotent (`server/go/internal/integrations/ghsnapshot/refresh.go:145`). A valid fetched timestamp plus nonempty snapshot head equal to current head constitutes hasFetched at the call site. Only hasFetched with age strictly below view TTL suppresses refresh; missing, stale, or head-mismatched snapshots enqueue (`server/go/internal/integrations/ghsnapshot/refresh.go:204`). Enqueue coalesces by installation/owner/repository/PR number, retaining one trailing request only for an in-flight address. Queue saturation drops and clears active bookkeeping for later triggers/sweep (`server/go/internal/integrations/ghsnapshot/refresh.go:171`).

The worker exits on cancellation; installation rate-limit waits occur outside worker slots (`server/go/internal/integrations/ghsnapshot/refresh.go:214`). Jitter cancellation, fetch errors/rate limits, and address lookup failure produce no application/event; last-known data remains. Rate limiting records installation Retry-After, with later view/webhook/sweep recovery rather than an unlimited retry loop (`server/go/internal/integrations/ghsnapshot/refresh.go:236`). Address lookup may use an eventual read: omitted candidates recover later, while primary writes guard against stale heads (`server/go/internal/integrations/ghsnapshot/refresh.go:309`). Each candidate has its own transaction; failures continue to other rows. Only an applied row invokes nonnil onApplied. Chase requires any applied row, an applied open/draft row, and an undecided snapshot, and is bounded (`server/go/internal/integrations/ghsnapshot/refresh.go:273`, `server/go/internal/integrations/ghsnapshot/refresh.go:464`). Trailing queue saturation likewise releases the address (`server/go/internal/integrations/ghsnapshot/refresh.go:379`).

The transaction updates snapshot fields guarded by head SHA, deletes/reinserts all check rows, and commits (`server/go/internal/integrations/ghsnapshot/refresh.go:410`). A zero-row guard returns false before check changes; begin/update/delete/insert/commit errors return without callback, with deferred rollback. Callback wiring is `server/go/internal/handler/handler.go:579`. After commit, callback PR or link SELECT failure silently returns; its void signature supplies no acknowledgement/retry (`server/go/internal/handler/github.go:1250`). The payload is a fresh post-commit PR projection and linked issue UUID array, not a frozen snapshot of the committing transaction. It publishes as system in the PR workspace (`server/go/internal/handler/github.go:1263`, `server/go/internal/handler/handler.go:792`).

Go therefore has a publication gap between commit and callback/bus delivery: process loss or callback SELECT failure can leave committed state without an event. Later refreshes can repair state visibility but are not durable replay of the lost event. Python must append an outbox envelope in the same successful guarded transaction as snapshot/check changes, then dispatch after commit with retries and at-least-once delivery; guard misses/rollbacks must not append. Existing append_event requires a caller transaction (`server/src/workpal_backend/infrastructure/outbox.py:19`). Omit empty optional actorID in Python because its envelope validator rejects empty optional strings. No Python snapshot producer, commit/rollback/recovery test, or runtime support is asserted by this evidence batch.

Go SubscribeAll forwards workspace events (`server/go/cmd/server/listeners.go:287`, `server/go/cmd/server/listeners.go:375`). Private audience resolution errors drop; private recipients receive workspace-member scopes (`server/go/cmd/server/listeners.go:339`). Linked issues resolve projects; membership is intersected across every private project, while no resolved private project retains workspace fanout (`server/go/cmd/server/private_project_realtime.go:110`, `server/go/cmd/server/private_project_realtime.go:228`). Websocket workspace selection and membership checking begin at `server/go/internal/realtime/hub.go:799`. This is workspace delivery, not a subscription to the viewed issue. Frontend onAny extracts the event prefix (`packages/core/realtime/use-realtime-sync.ts:1229`); pull_request invalidates all `[github,pull-requests]` queries, including summaries and issue lists (`packages/core/realtime/use-realtime-sync.ts:1094`, `packages/core/github/queries.ts:64`).

Proposed capability behavior: retain persisted linked PR reads and honest unknown/stale projections; report snapshot_available=false when disabled, matching enabled-aware response conversion (`server/go/internal/handler/github.go:193`, `server/go/internal/handler/github.go:234`). Disabled refresh must enqueue nothing or promise live updates. Unsupported explicit integration operations must fail explicitly. External production GitHub/model execution remains out of current scope. This proposal does not alter statuses, implement integrations, or invent supported operations.
