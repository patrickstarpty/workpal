# Plugin surface transport coverage

Bounded static closure: six bridge path families × five verbs, plus launch and hosted document navigation. The JSON records exact existing call IDs and route objects, including the inventory's misleading top-level GET on dynamic wrapper variants; actual verbs come from route.method. This audit does not change shared inventories.

`surface-bridge.ts:25–44` accepts context, issue, issue comments, workspace/user storage with optional key, and hooks with one nonempty slash-free segment. Every family accepts GET/POST/PATCH/PUT/DELETE independently. Server registration (`router.go:111–121,1759–1762`, constants `server/go/pkg/publicapi/v1/routes.go:14`) supports GET context; GET/PATCH issue; GET/POST comments; GET storage collection; GET/PUT/DELETE storage value; POST hook. Every other verb/family combination is bridge-permitted but unsupported by that server registration. No route is invented for it. Registered task messages are outside this bridge allowlist. Public bearer /v1 registration is a separate trust boundary, not the surface route.

`ApiClient.callPluginAction` (`client.ts:3656`) concatenates the raw path onto /api/plugin-bridge/v1, forwards method, JSON-stringifies a defined body, and sets X-Workpal-Plugin-Installation on the host session request. Only exact /context with truthy mounted issueId appends ?issue_id=encodeURIComponent(issueId); the handler reads issue_id (`plugin_action.go:294`). The wrapper does not encode or split dynamic segments. Regex [^/]+ permits ?, #, %, dot segments and other characters; /context?x fails, while /issues/id?x passes and URL parsing can separate its query. Storage keyed paths can similarly carry query text; collection paths with queries fail their anchored pattern. Fragments are not HTTP query parameters. Percent escapes/URL normalization can alter routing; acceptance does not establish a canonical target or valid issue/key. Handler uses issue_ref and scope/key URL params. Canonical route closure does not assert arbitrary raw-string routing equivalence.

Actual host chain: panel section and modal surface render PluginSurfaceFrame; it alone creates the bridge, which alone calls callPluginAction in non-test sources. Frame passes installation, launch token and optional issueId. pluginSurfaceLaunchOptions calls getPluginSurfaceLaunch; launchInstance/package version/issue distinguish query cache entries but are not launch HTTP parameters. client.ts:3594 encodes surfaceKey only, interpolating workspace and installation IDs. GET launch returns url and bridge_token. Handler constructs dedicated-origin /plugin-surfaces/{token} (`plugin_surface.go:209`); router registers GET resource serving. That browser resource request is distinct from the launch API and action API, and has no invented ApiClient call ID.

`surface-document.ts` validates http/https URL and token, embeds trusted outer srcdoc locally, assigns returned URL to nested sandbox=allow-scripts iframe src, and bounds frame-src to its origin. The hosted HTML request is network navigation; srcdoc, token encoding, theme forwarding, resize and MessagePort traffic are local. Guest-created port handshake requires child/outer window identity, protocol 2, matching challenge and one accepted connection. Host arms listener before srcdoc, sends current theme, forwards later themes, clamps resize to 0..4000, and closes on cleanup/navigation. Invalid request shapes are ignored; unsupported paths return local 400; action failures preserve numeric status or use 500. Successful callback returns local status 200 rather than exposing arbitrary HTTP success status.

No plugin execution, integration, network request, model call, runtime callback enumeration or Python compatibility is demonstrated. Static callback union is sufficient for this bounded audit; hosted plugin-defined outbound networking and arbitrary URL-normalization edge cases remain outside closure.
