## Registration, scope and identity

router.go:1766 installs Auth and :1767 RefreshCloudFrontCookies; :2191 registers PUT /api/issues/{id}; :2193 DELETE. There is no PATCH registration for this path. PUT has partial-update semantics, not replacement semantics. Bulk routes and separate status/workflow PATCH resources are excluded.

handler.go:1083 loadIssueForUser requires identity and resolved workspace, resolves identifier or UUID, queries within workspace and masks invisible private-project issues as 404 `{"error":"issue not found"}`. Missing workspace is 400 `workspace_id is required`; malformed workspace is 400 `invalid workspace_id`. Identity/membership middleware must remain in force before fixture assertions; fixtures assume authenticated authorized scope, not bypass headers. Unknown identifiers also return 404. Workspace membership resolution and token parsing are shared auth contracts, not redefined here.

Deletion additionally uses issue_delete_permissions.go:14: owner/admin can delete any visible issue; ordinary member may delete own issues or those created by agents currently owned in that workspace; bound agent may delete only its own. Machine credentials other than task tokens get 403 `issue deletion requires a human or a bound agent identity`; they do not inherit the token user's privileges. Permission check precedes task cancellation.

## PUT request and response

JSON lists every request field from UpdateIssueRequest (issue.go:3759). Invalid JSON/type yields 400 `invalid request body`. Unknown-field rejection is not installed by json.Unmarshal. `expected_revision` absent/null disables CAS; positive integer enables both initial comparison and SQL locked-row predicate. Nonpositive gives 400; stale gives complete 409 JSON in fixtures, including resolved UUID. Recheck a concurrent CAS loss after SQL returns no row (issue.go:4300 onward). title_base conflict uses handler.go:654 edit conflict shape without expected/actual revisions. Description baseline deliberately does not reject stale edits; descriptions are last-write-wins with channel media preservation.

Absent nullable fields retain existing values. Explicit null clears assignee_type/id, dates, parent, project and stage. Dates also clear for empty string. In contrast title/description/status/priority/position use pointer plus COALESCE: null and absence retain stored value. Clearing one assignee half can fail pair validation against the retained counterpart. No-op writes retain revision/timestamps per issue.sql:198; SQL increments revision only for actual field changes; position-only edits do not advance last_activity_at. Attachment linking may independently bump revision once. Complete no-op responses are in JSON, based on the minimal core seed; no extra detail/create-only fields should be inferred.

Status resolves active catalog key; priority validates enum. Parent must exist and be visible in same workspace; self-parent is rejected using resolved ID. Ancestor walk detects cycles for at most ten ancestors (do not claim unbounded detection). Project must exist and be visible in workspace; archived destination disallowed except resending current project. Project lookup backend failure gives 500 `failed to validate project`. Assignee pair validates membership/agent/squad and invoke authority, including private-agent originator policy; project-access check also applies when moving projects. Stage validation, triage-locked fields, duplicate marks and workflow remapping require their helpers, not generic nullable CRUD. Duplicate target visibility is checked before other field validation. Duplicate mark sets cancelled and reopening clears it; no explicit-null removal contract.

## Transactions and downstream boundaries

Publication is postcommit, not a Go transactional outbox guarantee.

Normal reassignment/status cancellation does not cancel active tasks. Explicit workflow handoff with stop_previous_assignee_runs can cancel prior assignee runs; suppress_run disables dispatch, not the mutation. dispatchIssueRun is conditional on willRun; child-parent events run for changed status/parent/stage and scheduler retries failures (issue.go:4415–4455). Execution-dependent operations must return explicit unsupported behavior in Python rather than fabricate a run. CRUD-only support must not pretend dispatch occurred; exact unsupported HTTP status/body remains a parent integration decision.

DELETE (:4617) first calls CancelTasksForIssue and best-effort FailAutopilotRunsByIssue BEFORE deletion transaction. These side effects are not rolled back with deletion failure. :4678 locks issue; detaches direct children; clears duplicate marks; gathers issue/comment attachment URLs; handles source-context clone attachments and durable object intents where Storage exists; deletes context and issue; commits. Children survive with parent removed; cleared duplicates remain cancelled. After commit deleteS3Objects (:1650 file.go) converts URLs to keys and calls DeleteKeys, with no result channel. Then issue:deleted carries resolved issue UUID and nullable project_id, followed by child snapshots and cleared-duplicate update snapshots; finally 204 with no body. No promise of recursive descendant deletion or synchronous successful byte deletion. Source-context intent recording is conditional on Storage and nonempty key; do not generalize it to every legacy attachment URL.
