# Workspace invitation contract

Source-derived evidence only; no Go differential execution or Python implementation claimed. Read alongside auth-workspaces-health.md: its session, CSRF, token-kind and membership policies apply unchanged. All seven routes and exact handler error strings are in the JSON. Decline is a discovered adjacent registration (POST /api/invitations/{id}/decline), outside this bounded create/list/revoke/accept deliverable.

## Authorization and identity

router.go authenticated group applies Auth and RefreshCloudFrontCookies. No invitation-specific RequireHumanActor registration: do not invent one or treat PAT/task credentials as interactive sessions. Workspace GET invitations is under RequireWorkspaceMemberFromURL; POST members and DELETE invitation require owner/admin. Task credentials retain workspace binding; absent membership returns 404 workspace not found, disallowed role 403. Recipient get/accept require user ID then load user and allow lower(user.email) == stored invitation email OR matching invitee_user_id. This comparison does not trim email. Personal list SQL compares stored user email directly OR user ID. GET /api/me is the identity lookup: missing stored user returns 401 user not found, query failure 500 failed to load user, otherwise userToResponse. There is no separate email-lookup registration in this route group; create uses internal GetUserByEmail. Invitation handlers issue no login cookies; shared auth may renew safe-request session and CloudFront cookies. Cookie writes retain CSRF enforcement.

## Lifecycle

Create decodes CreateMemberRequest; lowercases and trims email, requires nonempty but does not validate email syntax here. Empty role defaults member; otherwise trim and case-sensitive admin/member, owner rejected; whitespace-only role invalid. Existing membership conflicts 409. ExpireStalePendingInvitations updates <= now before live pending check; partial uniqueness includes all pending rows. Duplicate pending 409. UUID generated server-side, expiry now + seven days. Nullable invitee_user_id resolves existing user. Admission checks actor 10/10 minutes, workspace 50/day, recipient 6/day; recipient key SHA256 normalized email. 429 body includes error, code invitation_rate_limited and retry_after_seconds; Retry-After rounded up minimum one, Cache-Control no-store. Limiter outage 503 invitation_rate_limiter_unavailable, Retry-After 5. Capacity enabled branches reserve/compensate durable intents; external capacity execution is unsupported locally, never fabricate reservation success. Local disabled capacity path still persists invitation.

Lists return arrays ordered created_at descending, only pending with expires_at > now; workspace list enriches inviter name/email, personal list also workspace name. Single get permits concluded/expired rows and best-effort enrichment, does not mutate expiry. Invitation response always includes id/workspace_id/inviter_id/invitee_email/invitee_user_id/role/status/created_at/updated_at/expires_at; empty enriched strings omitted. Revoke verifies workspace and pending status, transactionally DELETEs pending row, requires exactly one affected row; no revoked status exists. Expired but still pending row may be revoked. Success 204 empty.

Accept ignores request body; UUID is lookup identity, not bearer authorization or a separate secret token. Recipient check precedes status/expiry. Accepted retry returns existing member 200, without events or onboarding write; missing membership 400 invitation is not pending, read failure 500 failed to load membership. Other concluded statuses 400. Pending expired strictly before now returns 410 invitation has expired; equality differs from list SQL. Transaction updates pending to accepted, creates member using accepted role, marks user onboarded with COALESCE and optionally transitions capacity intent, then commits. Unique member collision 409 you are already a member of this workspace rolls back acceptance. Concurrent conditional update failure yields handler 500 failed to accept invitation, not guessed idempotence. Member response uses memberWithUserResponse, not invitation response.

## SQLite map and boundaries

Translate workspace_invitation UUIDs to canonical TEXT; all required IDs/email/role/status/timestamps NOT NULL except invitee_user_id. role CHECK admin/member; status CHECK pending/accepted/declined/expired default pending. Preserve partial UNIQUE(workspace_id,invitee_email) WHERE status='pending' and two pending recipient indexes. Workspace deletion cascades; inviter and optional invitee references have default restrictive policy in migration 041; audit subsequent FK migrations before final DDL. UTC timestamps and explicit seven-day application default replace PostgreSQL now()/interval/gen_random_uuid. Member unique(workspace_id,user_id), role from invitation, generated ID/created_at defaults; onboarding update atomic and preserves existing timestamp. Do not introduce SQLite NOCASE semantics. Recheck pending state in short write transaction; no external I/O while locked. Create stale expiration is separate from create transaction in Go; do not claim atomicity across these writes.

## Producers and consumers

Create emits invitation:created {invitation, optional workspace_name}, actor requester, scope workspace, actor_type member, after persistence. Revoke emits invitation:revoked {invitation_id,invitee_email,invitee_user_id} after commit. Accept emits member:added {member,optional workspace_name}, invitation:accepted {invitation_id,member}, actor invitee, workspace scope, then notifyDaemonWorkspacesChanged. Accepted retry emits none. Reads emit none. TeamInviteSent/TeamInviteAccepted and first OnboardingCompleted are telemetry, not fabricated business outputs. listeners.go sends created/revoked to known invitee ID; accepted to actor excluding already subscribed workspace; member added also reaches invited user. Workspace broadcast and frontend realtime invitation cache invalidation remain required. Go post-commit Bus publish is not atomic outbox proof. Python migration requires mutation+event outbox transaction, stable IDs and retry/idempotent consumers.

Go email send is optional fire-and-forget after persistence and workspace-name lookup; failure logs and does not roll back invitation. Supported persistence must remain distinct from production delivery: local API must not report successful email delivery. Explicit unsupported delivery capability/error is a migration decision, not an observed Go response.
