## Decode and persistence

Handler uses one Go JSON Decode into a struct containing *json.RawMessage, limited to 16384 bytes. Empty/malformed body and top-level non-object/non-null return 400 {"error":"invalid request body"}. Unknown fields ignored; trailing values are not checked. Top-level null, absent questionnaire and questionnaire:null preserve stored value. Case-insensitive Go field matching applies. Duplicate questionnaire keys overwrite earlier raw values; final null clears the pointer and therefore preserves the old database value. Arbitrary non-null JSON is accepted, including scalar/array and incorrectly typed answer fields. No questionnaire validation occurs before SQL. Over-limit decode errors map to 400, not 413; trailing unread data need not trigger the cap. See server/go/internal/handler/onboarding.go:130 and server/go/internal/handler/onboarding.go:234.

Non-null replaces the entire JSONB value, never deep merges. With seed {"old":true}, questionnaire:{"role":"engineer"} yields exactly {"role":"engineer"}. questionnaire:{} clears answers. SQL COALESCE preserves only SQL NULL; the route cannot request JSON null storage. Every successful UPDATE sets updated_at=now(), even an empty patch. onboarded_at, created_at and other columns remain unchanged. Thus retries preserve questionnaire but are not timestamp-idempotent. See server/go/pkg/db/queries/user.sql:55.

GetUser errors are ignored, using empty prior answers. UPDATE errors and no returned row both yield 500 {"error":"failed to update onboarding"}; no 404 branch. Decode rejection precedes SQL. See server/go/internal/handler/onboarding.go:245.
