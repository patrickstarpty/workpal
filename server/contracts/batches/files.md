## Validation and fixtures

`file_upload_limits.go`: file cap 104857600 bytes inclusive; whole multipart cap 105906176. Oversize 413 `{error:"file exceeds the 100 MiB upload limit"}`; malformed multipart 400 `invalid multipart form`; missing file 400 begins `missing file field:`; read failure 400 `failed to read file`; storage write failure 500 `upload failed`. Go accepts zero-byte files and has no MIME allowlist. Sniff first 512 bytes; overrides `.svg,.css,.js,.mjs,.json,.wasm` in file.go extContentTypes; do not trust submitted MIME. Image dimensions derive from bytes, nullable for old/non-image records.

Bulk stable_attachment_urls capability suppresses remote signing; Python local bulk download_url remains stable.

Malformed UUID 400 via parseUUIDOrBadRequest; absent workspace 400 `workspace_id is required`; missing attachment 404 `attachment not found`; invalid workspace membership on upload 403 `not a member of this workspace`; issue/comment target invalid, hidden, deleted or wrong workspace 403 `invalid issue_id` / `invalid comment_id`. Validate comment's owning issue independently. Upload chat_session_id uses gatePublicChatSessionForUser, including member-visible chat projection/private-agent access. Never trust user-submitted actor/task headers. task_id requires middleware-authenticated task_token, exact task binding, same agent, workspace and chat task; browser client never sends task_id and Python must reject unavailable task execution explicitly.

## Byte serving

`file.go:1050–1110` and storage/util.go:79–110: local seekable serving matches http.ServeContent: 200 full, 206 single and multipart ranges, 416 unsatisfiable with Content-Range bytes */N; suffix/open-ended ranges, clamped end, zero-length object behavior and If-Range covered in file_test.go. Authorization must happen before opening bytes or parsing ranges. Cache-Control no-store, nosniff, Accept-Ranges bytes, exact Content-Length; no Last-Modified (Go zero modTime). Media image/video/audio/PDF inline except SVG; others attachment. Sanitize quoted filenames and supply RFC5987 filename* plus ASCII fallback for Unicode. dl=1 forces attachment. Preview CSP from attachmentPreviewCSPHeader forbids scripts/objects/base/form; frame ancestors self plus configured validated http(s) origins. Capability response adds Referrer-Policy no-referrer.

Text content is always text/plain; charset=utf-8, X-Original-Content-Type original, no-store/nosniff/CSP; no raw HTML execution. Whitelist exactly `server/go/internal/handler/attachment_text_preview.json` (text/*, listed application MIME/extensions/basenames). `server/go/internal/attachmentpreview/size.go`: default 2 MiB, WORKPAL_MAX_PREVIEW_SIZE positive bytes/KB/KiB/MB/MiB, clamp 16 MiB. Check metadata AND actual limit+1; 413 `file too large for inline preview`; 415 `preview not supported for this file type`; missing object 404 `attachment object not found`; read failure 502 `failed to read attachment body`. Missing ready bytes must be an explicit unavailable-content error, never 200 empty.

Capabilities: attachment_capability.go signs HMAC-SHA256 hex of `v1|id|exp`, adding `|attachment` for dl=1; key SHA256(`attachment-download-capability:` + JWT secret). TTL 60 seconds; expiry valid at exact exp second, rejected when now.Unix()>exp. Bad/missing signature, changed ID/expiry/intent: 403 `{error:"invalid or expired download link"}`. Mint only after authenticated ACL check; redemption deliberately does not recheck membership, but must find a ready extant attachment, so delete revokes immediately. Secret rotation revokes all. Preserve this bounded revocation policy; no remote S3/CloudFront execution in Python. Go remote redirects are 302 and default signing TTL 30 minutes; those are source context only.

## Persistence and events

Exact source schema: migrations 029,083,164,165,407,411,615; queries `server/go/pkg/db/queries/attachment.sql`. attachment: id UUID PK; workspace_id NOT NULL FK workspace CASCADE; nullable issue_id/comment_id/chat_session_id/chat_message_id FKs to corresponding id CASCADE; uploader_type member|agent check, uploader_id UUID NOT NULL polymorphic with NO FK; filename/url/content_type TEXT NOT NULL; size_bytes BIGINT NOT NULL; created_at timestamp NOT NULL default now; nullable integer width,height; task_id and source_context_id nullable UUID with NO FK. Index workspace and partial issue/comment/session/message/task/source-context. Translate UUID to validated text, timestamps to UTC, no PostgreSQL ANY/CTE modifying multiple tables or FOR UPDATE: explicit statements in one bounded SQLite transaction. Preserve parent cascades but enqueue byte cleanup before deleting parents; CASCADE alone loses storage keys.

CreateAttachment inserts and increments issue.revision and comment.revision atomically. DeleteAttachment deletes mutable row and increments both revisions atomically. Go upload uses withLiveCommentLock or wakeupWrite; delete uses withAttachmentOwnerLock, owner issue then live comment then child, rereads owner with max 3 attempts. Python finalization must revalidate live ownership after I/O and before ready transition, serialized with parent deletes.

Producer UploadFile successful issue association and DeleteAttachment changed issue emit `issue_attachments:changed` `{issue_id,issue_revision}` scoped workspace, actor uploader on create/current member on delete. Comment association also emits `comment:updated` `{comment: full serialized comment including reactions and remaining attachments}`. Go publishes AFTER transaction and reloads comment; Python append_event(session,event) MUST capture payload and stable event ID in the SAME transaction as ready/delete/revision changes, never commit independently. No event for unbound/avatar/chat-only upload or read; reason: these file handlers publish only issue/comment branches. Consumers `packages/core/realtime/use-realtime-sync.ts:1343,1450` invalidate issue attachment inventory/revisions and update comment cache. Task7 dispatch retries same event ID after Redis outage; client duplicate invalidation must be harmless.

Additional transactional producer: migration `520_collaboration_wakeup_events.up.sql:187–216` capture_attachment_wakeup INSERT/owner UPDATE/DELETE emits attachment.attached/detached only when coalesce(comment_id,issue_id) changes; skips source-context and chat rows. Payload attachment_id,target_type,target_id plus capture_issue_wakeup envelope. capture_issue_wakeup filters live issue, enabled event wakeups, event_types, agent/task filters and recursive wakeup context, then records wakeup effects inside the mutation transaction. Translate this via existing wakeup service in finalization/delete transaction, with actor/task provenance; do not enqueue model execution. Association producers LinkAttachmentsToIssue/Comment, ReplaceCommentAttachments, chat binding/detachment and parent teardown belong to their owner batches; expose cleanup/association interfaces below so they cannot bypass ready checks or ledger cleanup.

## Exact proposed implementation work items

All below paths prefixed server/. Create src/workpal_backend/files/{routes,schemas,service,repository,storage,reconcile}.py; migrations/versions/0006_upload_ledger.py; tests/test_files.py and tests/test_upload_recovery.py; browser test tests/python-web/files.spec.ts at repository root per plan.

- schemas.py: AttachmentResponse and multipart target parsing; serialize null links, optional dimensions and fresh URL fields explicitly.
- routes.py: bind the eight byte/metadata/delete routes above plus authorized avatar alias. Dependencies Task3 Principal and workspace guard; no public upload mount.
- storage.py: LocalBlobStore.create_staging(key,lease_token), write_bounded(stream,max_bytes)->(size,sha256,mime,dimensions), sync_and_promote(key,lease_token), open_ready(key), delete_owned(key,lease_token). Opaque generated keys, exclusive creation, same-filesystem staging, no-follow opens, resolved-root checks; client filename never part of key.
- repository.py: reserve_intent(session,principal,target,key,lease), renew_lease(session,id,token), finalize_ready(session,id,token,metadata), mark_deleting(session,id,principal), claim_expired(session,now,limit)->claims, complete_cleanup(session,claim). Conditional writes fenced by lease token/state; bounded busy retry. No transaction spans disk I/O.
- migration: upload_intent(id PK, attachment_id UNIQUE nullable, storage_key UNIQUE NOT NULL, staging_key UNIQUE, owner_type,owner_id,workspace_id nullable, target_json, state CHECK pending|ready|failed|deleting, lease_token,lease_expires_at,size_bytes,sha256,content_type,filename,width,height,next_attempt_at,last_error,created_at,updated_at). attachment/storage association must keep cleanup intent alive after attachment deletion (no cascading ledger deletion); user-owned avatar principal retained even without workspace. Index state/lease_expires_at/next_attempt_at. FK workspace deletion requires explicit cleanup scheduling before cascade; ledger target references are snapshots, not cascading FKs.
- service.py: upload(principal,scope,targets,stream)->AttachmentResponse; resolve_read(principal,id,scope,self_resolving=False)->ReadyAttachment; mint_capabilities(ready,now); delete(principal,scope,id)->None; schedule_owner_cleanup(session,attachment_ids); finalize_associations(session,attachment_ids,target). Guard all transitions; attach only ready rows. append mutation outbox and wakeup effects through transaction-owned collaborators.
- reconcile.py: reconcile_expired(database,store,now,limit)->counts; short claim transaction, cleanup outside transaction, short fenced completion. Worker Task7 registers durable scheduled job; API startup never runs its own scheduler.

Protocol: authorize/validate -> commit pending intent+lease -> stream exclusive staging with size/hash -> flush/fsync file -> atomic rename -> fsync parent directory -> short finalization transaction rechecking lease/authorization/owner liveness, insert attachment, revisions+outbox, mark ready -> response. Failed DB finalize after rename leaves pending recovery evidence, never returns a successful bare link (intentional correction to Go fallback). On delete transaction hide attachment and create durable deleting work+events before unlink. Retry unlink idempotently, ENOENT success; failed I/O retains retry state. Reconciler never deletes ready/live leased objects; expired pending may finalize only after all validation/ownership can be re-established, otherwise reclaim. Fencing prevents stale uploader finalizing after reclaim.
