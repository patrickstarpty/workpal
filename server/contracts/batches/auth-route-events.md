# Auth route event source audit

Scope: exactly POST /auth/send-code, /auth/verify-code, /auth/google and /auth/logout, traced from Go registrations. Event disposition means business realtime delivery, not absence of side effects or analytics.

## POST /auth/send-code

Disposition: `none`. SendCode validates email/disabled-account and signup eligibility (user lookup, optional live invitation SELECT only); rate limiter increments/expires Redis per-path/IP counters when configured, fail-open on Redis error. Latest-code lookup enforces 60-second cooldown, random code is inserted with ten-minute expiry, then SendVerificationCode delivers via SMTP or Resend (unconfigured development branch prints code), then best-effort expired-code deletion. These are security persistence and external email effects, not business realtime events. Email failure can leave the inserted code; no encompassing transaction, account creation, invitation acceptance, workspace provisioning, onboarding write or realtime publisher occurs.

## POST /auth/verify-code

Disposition: `none`. VerifyCode loads unused/unexpired code with attempts <5; wrong code increments attempts; valid/configured nonproduction dev code marks code used before account lookup, so later signup/token failure does not undo consumption. findOrCreateUser reads user, checks disabled/signup policy and optional pending invitation, inserts only a user when absent; it neither accepts invitations nor calls CompleteOnboarding/CreateWorkspace (separate endpoints). New-user edge emits analytics.Signup through metrics.RecordEvent: signup with user DistinctID, email_domain/signup_source properties and email/signup_source SetOnce; optional PostHog Capture queue or no-op plus Prometheus counters, not a workspace/user realtime broadcast. No encompassing transaction/outbox: signup telemetry follows user INSERT and precedes JWT/cookie success, with no rollback coupling. issueJWT generates random sid and signed stateless JWT; SetAuthCookies writes auth and token/session-bound CSRF cookies, optionally CDN cookies. There is no Redis session creation in this chain; Redis operations are route/IP rate-limit counters. No business realtime producer is reachable.

## POST /auth/logout

Disposition: `none`. Logout calls ClearAuthCookies then returns success. The helper expires auth and both CSRF cookies only. This public registration has no auth rate-limit wrapper; no user lookup, JWT denylist/session revocation, Redis session operation, database transaction, CDN-cookie clearing or realtime publisher occurs. Client cookie deletion is a security state change, not a business realtime event; an already issued bearer JWT is not revoked by this handler.

Sources: `server/go/cmd/server/router.go:1624`, `server/go/internal/handler/auth.go:797`, `server/go/internal/auth/cookie.go:307`.

Source audit only. No OAuth, email, model, network or runtime tests executed. No runtime delivery claims; no required realtime producer was found in these four bounded call chains. The Go behavior is the source of this audit, not evidence of Python implementation parity.
