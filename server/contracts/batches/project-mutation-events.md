# Project mutation event source audit

Source-derived only; no Go, Python or integration execution is claimed. The companion JSON contains three route records and checker-shaped event decisions, with separate producer, transaction and consumer source arrays. Actual registration is POST, PUT, DELETE; PATCH is not registered (`server/go/cmd/server/router.go:2330`, `:2333`, `:2334`). This bounded batch does not declare whole-inventory coverage.

POST follows `CreateProject` through the simple INSERT or the atomic private/resource transaction, then `Handler.publish` and synchronous `Bus.Publish`. Private membership initialization does not publish a membership event. Resource events follow the project event individually. Their project payload contains metadata and resource_count, while the HTTP transactional creation echo additionally contains resources. Creator attribution can differ from the hardcoded member event actor.

PUT follows `UpdateProject` into `writeProjectUpdate` (`project_member.go:295`). Empty prepared access uses a single UPDATE; access changes share a transaction with membership insertion, visibility and `TouchProjectSearchIndexEntries`. Nonempty prepared addIDs causes project:members_changed after commit, regardless of whether each requested member was newly inserted; project:updated follows with post-write aggregates. Visibility alone does not itself cause members_changed. Search synchronization rows for project, issues and comments are writes rather than extra bus event types.

DELETE follows the transaction in `project.go:784`: lock, clear chat references, delete project-scoped issue views, project members and subscribers, then project deletion and commit. SQL anchors are `chat.sql:6`, `issue_view.sql:75`, `project_member.sql` and `project_subscriber.sql`. The issue FK uses ON DELETE SET NULL (`034_projects.up.sql:19`); resources cascade (`065_project_resources.up.sql:7`). Autopilot project references use SET NULL (`097_autopilot_project_id.up.sql:2`). Project folder membership is the project's own soft folder ID, not a child deletion. Search-index-change triggers (`561_search_index_change.up.sql:90` and issue trigger) record project deletion and issue detachment. These changes do not cause handler publication of issue:updated, resource:deleted, view:deleted, chat events or membership events: only project:deleted is called after commit.

Audience is resolved by `private_project_realtime.go:112` and forwarded by `listeners.go:339`. Existing private projects narrow to member recipients and failures drop delivery. Project event invalidation reloads the private map. After deletion the project is absent, so the deletion ID falls back to workspace fanout; no old private audience snapshot is passed by this handler. Visibility transitions likewise use current audience. The actor and audience are distinct concepts.

Frontend generic dispatch splits on colon (`use-realtime-sync.ts:1231`); project prefix invalidates projects, workflows, issue tables and saved views (`:950`). This includes members_changed. The resource event prefix is project_resource, which has no handler in that generic dispatcher; the project creation event still invalidates project queries. This is a source observation, not proof of any running client's behavior.

Publication is outside the database transaction, with no durable outbox acknowledgement. Crashes can leave writes without events or partial multi-event publication. Bus listeners run synchronously and recover listener panics. The caller-owned Python outbox must persist intended rows atomically with writes if durable dispatch is required; these documents neither implement nor verify it. Preserve actual event payloads and conditional ordering when translating that boundary.
