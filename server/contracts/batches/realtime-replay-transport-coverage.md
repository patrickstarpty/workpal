## HTTP closure

All invalidation/refetch paths resolve against the existing conservative [active-web-auth-transport.json](active-web-auth-transport.json) `/transport_candidates` union, copied verbatim into this JSON's inventory with query_factory_evidence and frontend-calls IDs. This intentionally includes extra query factories; it requires no enumeration of mounted observers. Standard Tanstack semantics distinguish cache mutation/cancellation/removal from fetching, active invalidation from `refetchType: none`, and cold ensureQueryData from warm reads.

refreshMap covers inbox list/archive/unread and cross-workspace summary; workspace agents/members/list/skills/squads; project/workflow/issue table/view projections; all label scopes; status catalogs plus status-group predicates; pins; issue views; document predicates; runtimes/daemon agent snapshots; autopilot; GitHub/Lark/Slack/DingTalk/VCS/WeCom/Weixin/Telegram installations; pull requests/environments; agent activity/run counts/tasks and comment trigger preview. Specific issue handlers add detail/list/sidebar/table, unread/subscribed, attachments, timeline/activity, reactions/subscribers, task subtree/usage, metadata/properties and inbox projections. Specific chat handlers cover messages/pages/task messages, pending task and permission-filtered cross-session pending aggregate, sessions, draft restores and wakeups. They also patch local caches; a patch alone is not an HTTP call.

Reconnect and replacement-client effects call invalidateWorkspaceScopedQueries (lines 690–755): workspace, account invitations, issue projections, agents, chat, catalogs and per-issue caches, including inactive caches marked stale for later mount. Working-agent refresh cancels then invalidates filtered table/sidebar and presence/snapshot queries; task-message batching and aggregate timers preserve bounded read behavior. Generic debounce holds causes; the project activity timer does not restore cause context. Await boundaries also do not inherit synchronous observer causes. Recorder refusal therefore cannot establish a global no-write guarantee.

Explicit reads: resolveInboxSourceSlug uses ensureQueryData(workspaceListOptions); inbox/chat notifications use source-workspace notificationPreferenceOptions with explicit source slug, or warm-cache preference lookup if unresolved. Workspace-loss handling fetches workspaceListOptions then chooses navigation. refreshIssueUnread and refreshSubscribedIssues resolve to their own query factories. The exact source expressions and nested predicates are retained in JSON executable_inventory, rather than discarded from the ledger.

## Local and host effects

Chat message merging, pending promotion/removal, quick-action markers, stores and cache writes are local effects. Workspace loss clears local storage/search state and auth state, then window.location.assign navigates to a resolved destination. Toast is an optional injected UI callback. These do not define new API routes.

System notification delivery is separate: platform/system-notification.ts calls injected desktopAPI.showNotification or the browser Notification constructor. Native implementation is a precise external boundary, not covered desktop transport. Web onclick focuses the window and invokes the registered callback; apps/web/components/web-notification-bridge.tsx registers source-workspace inbox/chat navigation through useNavigation.push. Destination mounting and mark-read behavior are subsequent application navigation, not replay subscriptions.

hooks.ts has only event/reconnect subscription effects and status external-store reads, with cleanup. Caller callbacks remain caller-owned. provider.tsx gates connection by user/workspace/url/credentials, refreshes token on reconnect, forwards subscribe/reconnect/status, resets GitHub state on user change and separately attaches the local search index (existing search-index contract). Its generic host callbacks and search-index child scope are not silently classified as local-only or whole-source closed.
